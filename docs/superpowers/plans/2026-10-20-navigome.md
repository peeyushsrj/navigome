# Navigome Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A static single-page PWA behind the Pi's nginx that shows the current time-of-day life state (auto from clock, overridable by tap until window boundary) and lists that state's Vikunja tasks, toggleable to done.

**Architecture:** Vanilla-JS ES modules, no build step. Pure state logic in `statemachine.js` (unit-tested with `node --test`); Vikunja REST calls isolated in `vikunja.js` (10s timeouts, Bearer token from localStorage); DOM glue in `app.js`. Served at `/navigome/`, Vikunja proxied same-origin at `/vikunja-api/` → `127.0.0.1:3456` (no CORS).

**Tech Stack:** HTML/CSS/vanilla JS (ES modules), `node --test`, PWA (manifest + service worker), nginx on Raspberry Pi (`raspberrypi`, 192.168.1.38), Vikunja v2.7.0 REST API v1.

**Spec:** `docs/superpowers/specs/2026-10-19-navigome-design.md`

**Live API facts (verified 2026-10-20 against `GET /api/v1/docs.json`):**
- Auth: `Authorization: Bearer <token>` (works with existing `VIKUNJA_MCP_TOKEN`)
- List tasks: `GET /api/v1/tasks?filter=<vikunja filter>` — filter docs: https://vikunja.io/docs/filters
- Update task: `POST /api/v1/tasks/{id}` with JSON body (e.g. `{"done": true}`)
- Projects: `GET /api/v1/projects` → `[{id, title}]`
- Created projects: `14 Spiritual`, `15 Nature`

## Global Constraints

- No build step, no frameworks, no npm dependencies (except `node --test` = Node ≥18 built-in).
- ES modules only (`type="module"`); every function carries JSDoc `@param`/`@returns` types.
- Every external HTTP call: `AbortSignal.timeout(10000)` (spec §3.4).
- No secrets in repo: token + apiBase + override live in `localStorage` keys `navigome.token`, `navigome.apiBase`, `navigome.override`; never in committed files, never `console.log`ed.
- Default API base = `/vikunja-api` (same-origin proxy); Settings can override (direct LAN `http://192.168.1.38:3456` for pre-nginx use).
- State↔project mapping (spec §2 Option A, user-approved 2026-10-20) in `config.js` only:
  `morning:[14,12]`, `daytime:[6,7,10]`, `sunset:[15]`, `evening:[10,11]`, `night:[13]`.
- Default windows (editable in `config.js`): morning 05:00–09:00, daytime 09:00–17:30, sunset 17:30–18:30, evening 18:30–21:30, night 21:30–05:00 (midnight wrap).
- UI: compact, mobile-first — body 0.9em, headings ≤1.6em, padding ≤32px (AGENTS.md frontend tokens).
- Test command: `node --test statemachine.test.js` from project root.
- Commits after every task (project git initialized; baseline `2bb813e`).

## Review Focus

1. **Midnight wrap (night 21:30–05:00)** — at 23:00 and 04:00 the active state must be `night`, and `nextTransition` must cross midnight. → Task 2 tests: `stateFor` at 23:00/04:00, `nextTransition` at 23:00 → 05:00 next day.
2. **Override expiry exactly at boundary while page open** — tapping a chip holds that state only until the next window end; page must auto-revert without reload. → Task 2 tests: `resolveState` with unexpired/expired override; Task 5 manual check: set override near boundary, watch tick revert.
3. **Vikunja filter syntax may differ live (400)** — `filter=project_id = N` must be verified against the live API before UI depends on it; fallback = fetch tasks and filter client-side by `project_id`. → Task 4 Step 1 live-curl verification with explicit fallback branch.
4. **First load, no token** — must show banner + open Settings, not a blank page or console error. → Task 5 manual check + banner DOM id pinned in Interfaces.
5. **Subpath serving (`/navigome/`)** — all URLs relative (`./`), manifest `start_url:"."`, SW `scope:"./"`, else 404s behind nginx alias. → Task 6 verification behind nginx + Task 8 deploy checklist.

### Task 2: State machine (TDD)

**Files:**
- Create: `statemachine.js`, `statemachine.test.js`

**Interfaces:**
- Consumes: `config.js` shape (Task 1).
- Produces (ESM named exports, all pure, `now` = epoch ms, windows `["HH:MM","HH:MM"]`, end exclusive, start inclusive):
  - `parseHM(hm: string): number` → minutes since midnight; throws `RangeError` on invalid.
  - `stateFor(now: number, states: State[]): string | null` → active state id; first matching window; `null` if none (invalid window string skipped with `console.error`).
  - `overrideExpiry(states: State[], stateId: string, now: number): number | null` → epoch ms = end of `stateId`'s window (midnight-aware, may be next day); `null` if unknown id.
  - `resolveState(now: number, states: State[], override: {stateId: string, validUntil: number} | null): {stateId: string | null, mode: "auto" | "override"}` → override honored only if `now < validUntil` AND id exists.
  - `nextTransition(now: number, states: State[]): number | null` → epoch ms of next window boundary strictly after `now` (tests cover cross-midnight).

- [ ] **Step 1: failing tests** — `statemachine.test.js` using `node:test` + `node:assert/strict`, fixed dates in `Asia/Kolkata`-agnostic local time (construct via `new Date(2026, 9, 20, H, M).getTime()`):
  - `stateFor` 06:00→`morning`, 12:00→`daytime`, 18:00→`sunset`, 20:00→`evening`, 23:00→`night`, 04:00→`night` (wrap), exactly 09:00→`daytime` (boundary start-inclusive), 04:59→`night`.
  - `overrideExpiry(morning)` at 06:00 → same day 09:00; `overrideExpiry(night)` at 22:00 → next day 05:00.
  - `resolveState` unexpired → `{mode:"override"}`; expired (`validUntil` in past) → `{mode:"auto"}`; unknown id → auto.
  - `nextTransition` at 08:59→09:00 same day; at 23:00→05:00 next day (cross-midnight); at 18:00→18:30.
  - Invalid `"99:99"` window → skipped, `stateFor` still returns matching state / `null` otherwise.
- [ ] **Step 2:** Run `node --test statemachine.test.js` → FAIL (module missing).
- [ ] **Step 3:** Implement `statemachine.js` to Interfaces (minutes-based comparison; wrap = window where `start > end` matches `now ≥ start || now < end`).
- [ ] **Step 4:** Run → PASS (all above).

### Task 3: Vikunja client

**Files:**
- Create: `vikunja.js`
- Test: live verification (curl-equivalent via `fetch` in `node --test` NOT required; manual Step 1)

**Interfaces:**
- Consumes: none (takes `base: string, token: string` args everywhere).
- Produces (ESM named exports, all fetch with `AbortSignal.timeout(10000)`, throw `VikunjaError {status: number, body: string}` on non-2xx):
  - `listProjects(base, token): Promise<Array<{id: number, title: string}>>` → `GET {base}/api/v1/projects`
  - `listTasks(base, token, projectIds: number[]): Promise<Task[]>` where `Task = {id: number, title: string, done: boolean, due_date: string | null, priority: number, project_id: number}` → `GET {base}/api/v1/tasks?filter=<FILTER>`; `FILTER` built as `project_id = 14 || project_id = 12`-style OR (v1 filter syntax); **fallback:** if response `!ok` with 400 OR response lacks `project_id`, re-fetch per project `GET {base}/api/v1/tasks?filter=project_id = {id}`… if that also 400s → fetch once with no filter and filter client-side by `project_id ∈ projectIds`.
  - `setTaskDone(base, token, taskId: number, done: boolean): Promise<void>` → `POST {base}/api/v1/tasks/{taskId}` body `JSON.stringify({done})`.
  - `testConnection(base, token): Promise<{ok: boolean, message: string}>` — one `listProjects` call, maps 401 → "token rejected".

**Behavior (spec §4):**
1. On load: read `localStorage` (`navigome.token/apiBase/override`) → `resolveState(Date.now(), config.states, override)` → render header + chips (active chip = resolved state) → `listTasks` for active state's `projects` → render.
2. Ticks: `setInterval(1000)` updates `#clock` + `#next-transition` (`nextTransition` formatted `HH:MM`); `setInterval(30000)` re-resolves state (override expiry checked against `now` — spec model A) → refetch on state change only.
3. Chip click → `{stateId, validUntil: overrideExpiry(...)}` saved to `localStorage` → immediate re-render + refetch; `#override-badge` shows "manual — until HH:MM".
4. Checkbox → optimistic toggle → `setTaskDone` → on error revert + `#banner api-down`.
5. Task row: title, `due_date` (if set, `MMM D`), priority as 1–5 dots, `done` rows dimmed with strikethrough; empty state copy per spec §3.4.
6. Unmapped state (empty `projects`) → banner `unmapped` with text from spec §5.
